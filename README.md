# Bongo Cat for GNOME Shell

A Bongo Cat that taps along with your typing, shown in the GNOME top bar and
optionally on the desktop. It is a port of the
[DankMaterialShell `bongoCat` plugin](https://github.com/hthienloc/dms-plugins/tree/main/bongoCat)
by Loc Huynh (QML/Quickshell) to a GNOME Shell extension (GJS, GNOME 45–50).

## Requirements

- `libinput` CLI for **All Keyboards (Auto)** mode (Fedora: `libinput-utils`,
  Arch/Debian/Ubuntu: `libinput-tools`)
- `evtest` to monitor a single, specific keyboard
- Membership in the `input` group: `sudo usermod -aG input $USER`, then log out and back in
- Optional: `pw-play` (PipeWire, installed by default on Fedora) or `paplay` for
  key sounds with volume control. Without them, sounds play through libcanberra
  at system volume.

## Install

```bash
make install            # compiles the schema and copies to ~/.local/share/gnome-shell/extensions
# Wayland: log out and back in, then:
gnome-extensions enable bongo-cat@polyurethanegoose
```

`make zip` builds an installable `bongo-cat@polyurethanegoose.shell-extension.zip`
(`gnome-extensions install --force <zip>`).

## Usage

| Action | Result |
|---|---|
| Left-click the cat in the top bar | Open the menu (skin, colours, sliders, toggles, stats) |
| Right-click the cat | Toggle sleep mode |
| Desktop widget: left-drag / right-click | Move / toggle sleep |

Everything else is in the preferences window (`gnome-extensions prefs bongo-cat@polyurethanegoose`).

## Layout

| File | Ported from | Role |
|---|---|---|
| `extension.js` | `plugin.json` | enable/disable, wires model ↔ input ↔ sound ↔ UI |
| `lib/catModel.js` | logic in `BongoWidget.qml` / `BongoDesktopWidget.qml` | paw state machine, sleep/blink timers, WPM metrics |
| `lib/inputListener.js` | `shared/InputEventListener.qml` | runs `libinput`/`evtest` and parses their output |
| `lib/system.js` | `shared/InputDeviceScanner.qml` | device scan from `/proc/bus/input/devices`, tool and group checks |
| `lib/catView.js`, `lib/catDraw.js` | `shared/BongoCatView.qml` | Cairo rendering of both skins |
| `lib/catGlyphs.js` | `assets/bongocat-Regular.otf` | font outlines as path data (generated by `tools/generate_glyphs.py`) |
| `lib/sound.js` | `services/BongoSoundService.qml` | plays each hit via a short-lived `pw-play`/`paplay` process, libcanberra fallback |
| `lib/indicator.js` | bar pill + popout in `BongoWidget.qml` | `PanelMenu.Button` + `PopupMenu` |
| `lib/desktopWidget.js` | `BongoDesktopWidget.qml` | draggable actor in the background group |
| `prefs.js` | `BongoSettings.qml` + `shared/*Setting*.qml` | libadwaita preferences |
| `schemas/…gschema.xml` | DMS `pluginData` keys | GSettings |

## Development

```bash
make check     # renders preview.png with every pose/skin + runs logic tests (plain gjs, no Shell needed)
make glyphs    # regenerate lib/catGlyphs.js from the font (pip install fonttools)
make pot       # extract translatable strings
# Test in a nested shell (GNOME 49+: --devkit, older: --nested):
dbus-run-session gnome-shell --devkit --wayland
journalctl -f -o cat /usr/bin/gnome-shell | grep -i bongo
```

## Differences from the DMS plugin

- **One shared input reader and state.** DMS ran one `libinput` process per bar
  instance and de-duplicated sounds. Here a single listener drives both the top
  bar cat and the desktop cat.
- **Mouse reactions in specific-keyboard mode now work.** In the original, the
  second `libinput` process emitted a signal that the widget never handled.
- **The "Theme Primary" colour is now "Accent Color".** It follows GNOME's accent
  colour on GNOME 47+ and falls back to Adwaita blue on older versions.
- **The custom colour is picked in Preferences.** GNOME Shell has no colour-picker
  modal that can be used from a menu.
- **Sliders and dropdowns** are GNOME menu sliders and submenus. Picking a
  submenu entry closes the menu, which is standard GNOME behaviour.
- **The input listener restarts with backoff** (1 s → 30 s) when
  `libinput`/`evtest` exits, for example after unplugging a device.
- **The cat stops while the screen is locked.** The extension is disabled on the
  lock screen, so key presses there are never read.
- **Nothing blocks the Shell's main thread.** Audio runs in helper processes
  (an earlier in-process GStreamer version could freeze the whole session at
  login), input reading starts only after the Shell has finished starting, and
  the setup checks only read files.
- **Translations are not ported.** The originals were almost empty (at most 5 of
  79 strings per language). Gettext is wired up; use `make pot` to start new ones.
